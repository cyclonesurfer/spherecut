## MCP, clients and SDKs

- The current MCP specification revision is 2026-07-28, released on 2026-07-28. The docs navigation labels it 'Version 2026-07-28 (latest)'. The previous revisions are 2025-11-25, 2025-06-18, 2025-03-26 and 2024-11-05. (verified; github.com/modelcontextprotocol/modelcontextprotocol main: docs/docs.json version list; https://blog.modelcontextprotocol.io/tags/protocol/ (post 'The 2026-07-28 Specification', July 28, 2026))
- 2026-07-28 removes the initialize/notifications/initialized handshake, ping, logging/setLevel and notifications/roots/list_changed. Every request carries io.modelcontextprotocol/protocolVersion and clientCapabilities in _meta. Servers MUST implement server/discover. All results carry resultType ('complete' or 'input_required'). tools/list and the other list results carry ttlMs and cacheScope. UnsupportedProtocolVersion is -32022. Servers SHOULD return tools in a deterministic order. (verified; docs/specification/2026-07-28/changelog.mdx, major items 2, 3, 5, 8 and minor items 3, 5, 12 (raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main))
- Era compatibility: a 'legacy' client (one that sends initialize, 2025-11-25 and earlier) against a modern-only server FAILS, and legacy clients have no way to move forward. A dual-era server MAY serve both in the same process: an initialize request selects legacy semantics for that stdio process, and a request with modern _meta is served statelessly. (verified; docs/specification/2026-07-28/basic/versioning.mdx:126-183 (compatibility matrix row 'Legacy | Modern | Fails'))
- stdio framing in 2026-07-28: the server reads JSON-RPC from stdin and writes it to stdout, one message per line. Messages are delimited by newlines and MUST NOT contain embedded newlines. The server MAY write UTF-8 logs to stderr, and clients SHOULD NOT treat stderr output as an error. The server MUST NOT write anything to stdout that is not a valid MCP message, and MUST NOT write JSON-RPC requests at all (server-to-client questions go through InputRequiredResult). Servers SHOULD exit promptly on stdin EOF. The same framing may be reused over Unix sockets. 2025-11-25 has the same newline and stderr rules. (verified; docs/specification/2026-07-28/basic/transports/stdio.mdx:10-31, 55-58, 102-104; docs/specification/2025-11-25/basic/transports.mdx:28-32)
- Cancellation on stdio: the client MUST send notifications/cancelled with the requestId. The server SHOULD stop and MUST NOT send further messages for that request, and both sides must tolerate races. Servers MUST NOT send notifications/cancelled except to end a subscriptions/listen stream. Progress: the server MAY send notifications/progress only if the request's _meta has a progressToken, and the progress value MUST increase. (verified; docs/specification/2026-07-28/basic/transports/stdio.mdx:76-83; basic/patterns/cancellation.mdx; basic/patterns/progress.mdx)
- Legacy-era requirements (2025-11-25): initialize must come first. The server echoes the client's requested version if it supports it, otherwise it answers with its own latest. The client then sends notifications/initialized. ping MUST get a prompt empty response. (verified; docs/specification/2025-11-25/basic/lifecycle.mdx:40-175; basic/utilities/ping.mdx:29)
- Roots, Sampling and Logging are deprecated as of 2026-07-28, with at least a 12-month window. Roots are 'informational guidance rather than an access-control mechanism'. The spec's suggested migration is to pass directories through tool parameters, resource URIs or server configuration. Elicitation, sampling and roots/list now travel through Multi Round-Trip Requests (InputRequiredResult) instead of server-initiated requests. (verified; docs/specification/2026-07-28/changelog.mdx 'Deprecated' item 1 and major item 7; docs/specification/2026-07-28/client/roots.mdx)
- Tool result content types: text; image {type:'image', data: base64, mimeType}; audio; resource_link {uri, name, mimeType}; embedded resource. structuredContent may be any JSON value (2026-07-28) and must conform to outputSchema if one is given. A tool returning structuredContent SHOULD also return the serialized JSON in a TextContent block. Input validation and business errors are tool execution errors (isError: true); an unknown tool is a JSON-RPC error -32602. (verified; docs/specification/2026-07-28/server/tools.mdx:405-520, 755-785; changelog minor item 10)
- Security text in the tools spec: servers MUST validate inputs, implement access controls, rate-limit and 'sanitize tool outputs'. Clients MUST treat tool annotations as untrusted unless the server is trusted. The ToolAnnotations hints are readOnlyHint, destructiveHint, idempotentHint and openWorldHint. (verified; docs/specification/2026-07-28/server/tools.mdx:302-306, 787-801; schema/2026-07-28/schema.ts:1912-1953)
- MCP 2026-07-28 has no protocol-level session. State that spans calls should be held under an explicit, server-minted, non-guessable handle passed as a tool argument. List endpoints must not vary per connection. A crashed stdio server SHOULD be restarted by the client, and in-flight requests are lost. (verified; docs/specification/2026-07-28/server/tools.mdx (handles section, ~lines 690-745); basic/transports/stdio.mdx:109-115; docs/docs/2026-07-28/tutorials/security/security_best_practices.mdx:516-557)
- MCP security guidance for local servers: use stdio so that only the client can reach the server, or, for other transports, Unix sockets or IPC with restricted access. There is no specific guidance on prompt injection through tool output beyond 'sanitize tool outputs' and the client-side 'validate tool results before passing to LLM'. (verified; docs/docs/2026-07-28/tutorials/security/security_best_practices.mdx:606-652; server/tools.mdx:787-801)

## What agents pay for

- Claude's visual-token cost of an image is ceil(width/28) x ceil(height/28). The standard tier caps images at 1,568 px on the long edge and 1,568 tokens; the high-resolution tier (Claude 4.7 and later) caps them at 2,576 px and 4,784 tokens.
